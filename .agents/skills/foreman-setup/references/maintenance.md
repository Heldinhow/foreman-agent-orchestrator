# Setup maintenance and roadmap use

## Resume or update

Read existing setup progress and owning records before new research. Resume pending questions/assignments rather than duplicating Workers or restarting the interview. Process changes as a delta: added source, changed revision/contract, corrected answer or new goal.

Reopen affected gaps when evidence conflicts or becomes stale. Preserve the previous decision's source and superseding rationale. Request confirmation for materially changed goals, scope or dependencies. Update setup readiness for the affected scope; `ready` is not permanent proof of freshness.

Before a later task, retrieve the relevant project notes, relationships, decisions and evidence from the context index. Include unresolved gaps in the Worker brief. Recheck findings when revisions, interfaces or operator reports challenge them; there is no background freshness guarantee.

## Roadmap requested

Use confirmed product outcomes, users/journeys, current capabilities, constraints and dependency impact to frame a proposal. Distinguish committed work from ideas. Each proposed item names its intended outcome, rationale, dependency assumptions and unknowns. Time/capacity estimates without evidence are explicitly provisional.

Ask the operator about missing priorities or strategic trade-offs; repository structure alone cannot establish business value. Delegate engineering investigation to independent Workers as needed. Present the roadmap as a proposal for human confirmation, not an authorization to implement its items.

This setup skill provides context for roadmap work; it does not create a roadmap automatically or promise complete product knowledge.
